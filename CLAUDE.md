# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A demo repo for Docker's "Running AI agents in GitHub Actions with Docker Sandboxes" pattern. A `gh-aw` workflow runs a Copilot agent inside a Docker Sandbox (`sbx`) microVM on an `ubuntu-24.04` runner. The agent runs Testcontainers-based Java tests against the sandbox's private Docker daemon, finds a seeded bug, and a separate safe-output job opens a draft PR limited to `src/**`. `SPEC.md` is the original spec; `README.md` is the user-facing walkthrough.

## Critical rule: the seeded bug must stay

The case-sensitive email uniqueness bug in `RegistrationService` is the point of the demo. **Do not fix it, and do not commit a case-variation test.** The agent in CI is meant to find both. Keep `register()` free of normalization and of hint comments, and keep the schema's plain `TEXT NOT NULL UNIQUE` (no `citext`, no `lower(email)` index). `RegistrationServiceIT` has exactly two tests (`registersNewEmail`, `rejectsExactDuplicate`).

To re-prove the bug or the one-line fix (`email.trim().toLowerCase(Locale.ROOT)` before insert), add the case test or the fix temporarily, run the suite, then `git checkout -- src` and confirm `src/` is clean.

## Commands

Docker is the only prerequisite; there is no local Maven or JDK requirement.

- All tests: `./scripts/test-in-docker.sh`
- One test: `./scripts/test-in-docker.sh -Dtest=RegistrationServiceIT#rejectsExactDuplicate` (arguments go to `mvn --batch-mode <args> test`)
- Compile the agent workflow: `gh aw compile sandbox-explorer` (needs the `gh-aw` extension and `gh` auth)
- Lint: `shellcheck scripts/test-in-docker.sh`; yamllint on `.github/workflows/kvm-probe.yml`

## Architecture

- `src/main/.../registration/`: `RegistrationService` (plain JDBC over a `DataSource`, creates the schema from `Schema.DDL` in its constructor, `register()` returns `false` on SQLState `23505`) and `Schema`.
- `src/test/.../RegistrationServiceIT.java`: Testcontainers PostgreSQL. Surefire includes `*Test` and `*IT`, so `mvn test` runs it.
- Testcontainers is 2.x: artifacts are `testcontainers-postgresql` and `testcontainers-junit-jupiter`, and the container class is the non-generic `org.testcontainers.postgresql.PostgreSQLContainer`. A digest-pinned image name needs `DockerImageName.parse(...).asCompatibleSubstituteFor("postgres")`.
- `scripts/test-in-docker.sh` runs Maven in a digest-pinned container with `/var/run/docker.sock` mounted. PostgreSQL starts as a sibling container, so the Maven container reaches it through `--add-host=host.testcontainers.internal:host-gateway` and `TESTCONTAINERS_HOST_OVERRIDE`. Inside a sandbox, that socket is the sandbox's private daemon.

## Workflows (`.github/workflows/`)

- `sandbox-explorer.md` is the human-authored gh-aw source. `sandbox-explorer.lock.yml` is generated by the compiler: **never hand-write or edit it**. It is intentionally absent until someone with `gh-aw` runs the compile. The recompile reminder sits below the frontmatter, because frontmatter must be the first thing in the file.
- The frontmatter is deliberately minimal and read-only: `workflow_dispatch` only, `contents: read` and `copilot-requests: write`, `sandbox.agent {id: awf, runtime: docker-sbx}`, and `safe-outputs.create-pull-request` with `draft: true`, `protected-files: blocked`, `allowed-files: ["src/**"]`. Don't widen these. Don't install `sbx` in any step, because the compiled workflow does it.
- gh-aw's frontmatter schema moves fast. The spec's `sudo: true` is rejected as of v0.89.21 (it was valid in v0.85.x, which the reference repo `shelajev/docker-sandbox-gh-aw-demo` used), so it is omitted. When a compile fails on a key, check the schema at `https://raw.githubusercontent.com/github/gh-aw/<tag>/pkg/parser/schemas/main_workflow_schema.json` (match the user's `gh aw version`) rather than the docs site, which lags.
- The prompt guardrails are advisory. The enforced boundaries are the sandbox, the network allowlist, the read-only token, and `allowed-files`.
- `kvm-probe.yml` is a hand-written manual check that `/dev/kvm` is usable on the hosted runner.

## Conventions

- Container images are pinned by digest (Maven image in the script, `postgres:16.6-alpine` in the IT, `alpine:3.21` in the agent prompt). Resolve real digests with `docker buildx imagetools inspect`; never invent one. Dependency versions in `pom.xml` are pinned.
- Shell scripts need `set -euo pipefail` and LF endings (enforced by `.gitattributes`).
- Report only what was actually verified. A real Actions run needs the user's repo and secrets (`DOCKER_USERNAME`, `DOCKER_PAT`, Copilot access), so it can't be verified from here.
